## 1. MVP設計

### 1.1 コンセプト

「AgentFlow」（仮称） - 日本語ネイティブ対応のマルチエージェント業務自動化プラットフォーム。
中小企業（50〜500人規模）が、ノーコードで複数のAIエージェントを作成・連携させ、定型業務を自律実行させる基盤。

### 1.2 最小機能セット（5機能）

| # | 機能 | 概要 | 優先度 |
|---|------|------|--------|
| 1 | **エージェントビルダー** | GUIでAIエージェントを定義（役割、入出力、使用ツール）。テンプレートから選択 or カスタム作成 | 必須 |
| 2 | **ワークフローエディタ** | エージェント間の連携フローをドラッグ&ドロップで構築。トリガー条件・分岐・並列実行に対応 | 必須 |
| 3 | **外部サービス接続（コネクタ）** | Gmail、Slack、Google Sheets、Salesforce、kintone等との連携。初期は5〜8コネクタ | 必須 |
| 4 | **実行モニター＆ログ** | ワークフローの実行状況をリアルタイム可視化。エラー時の通知と手動介入ポイント | 必須 |
| 5 | **テンプレートライブラリ** | 「営業フォローアップ自動化」「問い合わせ対応」等のプリセットワークフロー（初期5〜10本） | 重要 |

### 1.3 MVPで意図的に含めないもの

- 自然言語だけでのワークフロー構築（v2以降）
- エージェント間の自律的な協調（v1はフロー定義ベース）
- オンプレミス対応
- カスタムLLMモデルの持ち込み

### 1.4 技術スタック

| レイヤー | 技術 | 選定理由 |
|----------|------|----------|
| **フロントエンド** | Next.js 15 (App Router) + TypeScript | SSR/ISR対応、React Flowでワークフローエディタ実装 |
| **UIライブラリ** | shadcn/ui + React Flow | ワークフロー可視化に特化、カスタマイズ性 |
| **バックエンド** | Next.js API Routes + Hono (ワーカー用) | メインはNext.js、エージェント実行エンジンはHono on Cloudflare Workers |
| **エージェントエンジン** | LangGraph (TypeScript) | マルチエージェントオーケストレーション、状態管理が堅牢 |
| **LLM** | OpenAI GPT-4o（メイン）+ Claude 3.5 Sonnet（サブ） | コスト効率と品質のバランス、日本語品質 |
| **DB** | Supabase (PostgreSQL) | 認証・リアルタイム・ストレージ一体型、開発速度重視 |
| **キュー/実行管理** | Inngest or Trigger.dev | ワークフロー実行のスケジューリング・リトライ・監視 |
| **インフラ** | Vercel (フロント) + Cloudflare Workers (エージェント実行) | エッジ実行でレイテンシ低減、スケーラブル |
| **監視** | Sentry + Langfuse | アプリ監視 + LLMオブザーバビリティ |

## 3. リスクと対策

### リスク1: AI APIコストの高騰・不安定性

| 項目 | 内容 |
|------|------|
| **リスク内容** | OpenAI/Anthropicの価格改定、レートリミット、サービス障害でコスト急増や機能停止 |
| **発生確率** | 高（過去に複数回の価格変更・仕様変更あり） |
| **影響度** | 大（粗利率が一気に悪化、SLA違反） |
| **対策** | (1) マルチLLMアーキテクチャを初期から採用（GPT-4o / Claude / Gemini 切替可能） |
| | (2) 軽量タスクはローカルSLM（Phi-3等）にオフロードする設計 |
| | (3) 利用量ベースの課金モデルでコスト転嫁を可能にする（従量課金オプション） |
| | (4) LLM応答のキャッシュ層を設け、同一パターンの再利用率を上げる |

### リスク2: エンタープライズ競合の日本市場参入

| 項目 | 内容 |
|------|------|
| **リスク内容** | Microsoft Copilot Studio、Salesforce AgentForce等が日本語対応を強化し、中小企業向けにも展開 |
| **発生確率** | 中〜高（2026年後半〜2027年に本格化の見込み） |
| **影響度** | 大（既存顧客のスイッチングリスク、新規獲得の困難化） |
| **対策** | (1) 日本特有の業務ツール（kintone、freee、Money Forward、ChatWork）への深い連携を差別化要素に |
| | (2) 導入支援・伴走サポートを含む「コンサル込みSaaS」で、大手にない手厚さを提供 |
| | (3) 業種特化テンプレート（製造業の受発注、不動産の物件紹介等）でスイッチングコストを高める |
| | (4) 早期に100社の導入実績を作り、事例ベースのマーケティングで信頼を確立 |

### リスク3: エージェントの品質問題（誤動作・ハルシネーション）

| 項目 | 内容 |
|------|------|
| **リスク内容** | AIエージェントが誤った判断で業務を自律実行し、顧客企業に損害を与える（誤送信、データ破壊等） |
| **発生確率** | 中（LLMの特性上、ゼロにはできない） |
| **影響度** | 極大（信頼喪失、賠償リスク、解約連鎖） |
| **対策** | (1) **Human-in-the-Loop**をデフォルト設定にし、重要アクション（送信・削除・更新）は承認ステップを挟む |
| | (2) 段階的な自律度設定（監視モード → 提案モード → 自律モード）を提供 |
| | (3) ドライラン機能で実行前にシミュレーション結果を確認可能に |
| | (4) 利用規約にAIの限界を明記し、損害保険（サイバー保険）に加入 |

## 4. 請負事業とのシナジー

### 4.1 顧客パイプラインの相互送客

```
請負 → AgentFlow:
  大手請負先の子会社・関連中小企業に AgentFlow を提案
  （大手の信頼をテコに紹介営業）

AgentFlow → 請負:
  AgentFlow導入企業がカスタム開発ニーズを持つケースで請負受注
  （コネクタ開発、業務システム連携、ダッシュボード構築等）
```

- 請負の既存顧客に「業務自動化の提案」として自然にAgentFlowを紹介可能
- AgentFlowのカスタムコネクタ開発やシステム連携は、請負チームがそのまま受託できる
- 想定: 1年目は新規顧客の30%（約15社）を請負経由で獲得

### 4.2 技術・ナレッジの共有

| 請負で得るもの | AgentFlowに活かす方法 |
|--------------|---------------------|
| 大手企業の業務フロー知見 | テンプレートの品質向上、エンタープライズ機能の先読み |
| 多様なAPI/SaaS連携経験 | コネクタ開発の速度とカバレッジ向上 |
| セキュリティ要件の知見 | SOC2/ISMS対応の設計に反映 |
| フロントエンド開発力 | ワークフローエディタのUI/UX品質向上 |

### 4.3 リソースの柔軟配分

- 請負の谷間期間にAgentFlowの開発リソースを集中投入
- AgentFlowの開発で得たAIエージェント技術を請負案件の付加価値に（「AI機能付きWebアプリ開発」として単価UP）
- 外注エンジニアを請負 / AgentFlowで共有し、稼働率を最大化

### 4.4 ブランド効果

- 「大手企業のシステム開発実績がある会社が作ったAIプラットフォーム」という信頼性
- 請負のポートフォリオに「自社SaaSも運営」を追加することで、技術力の証明になる
- 中長期的には、AgentFlowの成長がバリュエーション向上に直結し、資金調達やM&Aの選択肢を拡大

### 4.5 収益ポートフォリオの安定化

| | 請負事業 | AgentFlow |
|--|---------|-----------|
| 収益特性 | 一括・案件ベース | MRR（月次課金） |
| 利益率 | 20〜30% | 60〜70%（成熟時） |
| スケーラビリティ | 人月に比例 | 人月に非依存 |
| キャッシュフロー | 前払い or マイルストーン | 月次安定入金 |

請負の安定キャッシュフローでAgentFlowの初期赤字をカバーし、AgentFlowの成長で会社全体の利益率とバリュエーションを押し上げる構造。
