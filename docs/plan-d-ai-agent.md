# 事業プランD: 業種特化AIエージェント - 士業事務所向け

## エグゼクティブサマリー

特定業種として**税理士・会計事務所**を選定し、記帳・仕訳・顧問先対応を自動化するAIエージェント「**AI経理パートナー**」を開発する。月額2.5万円〜のSaaSとして提供し、3年目に月商1,500万円・営業利益率30%を目指す。

---

## 1. MVP設計

### 1-1. 選定業種: 税理士・会計事務所

**選定理由（5つの観点）**

| 観点 | 評価 | 根拠 |
|------|------|------|
| 市場規模 | ◎ | 全国約3.4万の税理士事務所、約3万の会計事務所。合計約6万事業所 |
| 業務の定型性 | ◎ | 記帳・仕訳・申告書作成は明確なルールベース。AIとの相性が極めて高い |
| IT化の遅れ | ◎ | 弥生・freee・MFは普及しているが「入力作業」自体は人手。AIエージェントの空白地帯 |
| 支払い能力 | ○ | 顧問料月3〜5万円/社が相場。ツール投資への理解がある業種 |
| 法規制の参入障壁 | ◎ | 日本の税法・会計基準への対応が必須。海外AIツールが直接参入しにくい |

**競合比較**

| サービス | 位置づけ | AI経理パートナーとの差別化 |
|----------|----------|--------------------------|
| freee / MF | クラウド会計ソフト | 入力は人間がやる前提。AIエージェントではない |
| ChatGPT / Claude | 汎用AI | 会計・税務の専門知識が浅い。仕訳の正確性に課題 |
| 各社AI機能 | 既存ソフトの付加機能 | レシート読取など部分的。業務全体の代行ではない |
| **AI経理パートナー** | **業務代行AIエージェント** | **仕訳判断→入力→確認依頼→修正まで一気通貫** |

### 1-2. 最小限の機能セット（MVP: 5機能）

**機能1: 証憑AIスキャン & 自動仕訳**
- レシート・請求書・通帳のスキャン画像をアップロード
- OCR + LLMで内容を読み取り、勘定科目を自動判定
- 過去の仕訳パターンを学習し、精度を継続的に向上
- 不確実な仕訳はフラグ付きで人間に確認依頼

**機能2: 顧問先チャットボット（LINE/Web）**
- 顧問先（クライアント企業）からの定型質問に自動応答
- 「この経費は落ちますか？」「届出の期限はいつ？」等
- 事務所ごとの回答ポリシーをカスタマイズ可能
- 対応できない質問は担当者にエスカレーション

**機能3: 月次処理アシスタント**
- 月次決算の未処理項目を自動チェック
- 前月比の異常値を検出しアラート
- 月次レポートのドラフトを自動生成
- 担当者のレビュー待ちタスクを一覧表示

**機能4: 税務カレンダー & リマインド**
- 顧問先ごとの申告・届出期限を自動管理
- 期限の2週間前・1週間前・3日前にアラート
- 必要書類の準備状況をチェックリストで管理
- 法改正による期限変更を自動反映

**機能5: ナレッジベース（事務所内FAQ）**
- 事務所内の判断基準・過去事例を蓄積
- 新人スタッフが検索して自己解決できる仕組み
- 「この場合の仕訳はどうする？」→ 過去事例から回答
- ベテランの暗黙知をAIが構造化して保存

### 1-3. 技術スタック

| レイヤー | 技術 | 選定理由 |
|----------|------|----------|
| フロントエンド | Next.js 15 (App Router) + Tailwind CSS | Webアプリ得意領域を活かす。SSRでSEO対策 |
| バックエンド | Next.js API Routes + Hono (一部) | フルスタックで開発効率最大化 |
| データベース | Supabase (PostgreSQL) | 認証・DB・ストレージ一体。開発スピード重視 |
| AI/LLM | Claude API (Anthropic) | 日本語性能が高い。Tool Use対応でエージェント構築に最適 |
| OCR | Google Cloud Vision API | 日本語OCR精度が高い。レシート・請求書対応 |
| ベクトルDB | Supabase pgvector | ナレッジベース用。追加インフラ不要 |
| ファイルストレージ | Supabase Storage | 証憑画像の保存。S3互換 |
| LINE連携 | LINE Messaging API | 顧問先チャットボット用。日本の中小企業はLINE利用率が高い |
| 認証 | Supabase Auth | 事務所・顧問先の多層認証 |
| インフラ | Vercel + Supabase | サーバーレス。初期インフラコスト最小 |
| 監視 | Sentry + Vercel Analytics | エラー監視・パフォーマンス計測 |

## 3. リスクと対策

### リスク1: AIの仕訳精度が実用レベルに達しない

| | 内容 |
|--|------|
| 発生確率 | 中 |
| 影響度 | 大（サービスの根幹に関わる） |
| 具体的シナリオ | 仕訳の正答率が90%以下だと、人間の確認コストが減らず価値が出ない |
| **対策1** | MVP段階で「確信度スコア」を導入。確信度が低い仕訳は必ず人間に確認させる。精度100%を目指さず「人間の作業量を60%削減」をKPIにする |
| **対策2** | 事務所ごとの過去仕訳データでファインチューニング（Few-shot学習）。使うほど精度が上がる仕組みにし、スイッチングコストも高める |
| **対策3** | 初期は特定業種の顧問先（飲食店、小売業など仕訳パターンが定型的な業種）に絞り、対応範囲を段階的に拡大 |

### リスク2: 既存会計ソフトベンダー（freee, MF, 弥生）がAIエージェント機能を実装

| | 内容 |
|--|------|
| 発生確率 | 高 |
| 影響度 | 大（市場シェアを奪われる可能性） |
| 具体的シナリオ | freeeやMFが自社プラットフォーム上でAI仕訳エージェントをリリース |
| **対策1** | 「会計ソフトの補完」というポジショニングを徹底。freee/MF/弥生との連携APIを実装し、競合ではなくエコシステムの一部になる |
| **対策2** | 「事務所の業務フロー全体」をカバーし、単なる仕訳自動化を超える。顧問先コミュニケーション、ナレッジ管理など会計ソフトがカバーしない領域で差別化 |
| **対策3** | 大手が動く前に100社以上の導入実績とケーススタディを積み上げ、「税理士事務所向けAI=AI経理パートナー」のブランドを確立 |

### リスク3: 顧客獲得コストが想定を上回る

| | 内容 |
|--|------|
| 発生確率 | 中〜高 |
| 影響度 | 中（収益化の遅延） |
| 具体的シナリオ | 税理士事務所は保守的で、新しいツール導入に慎重。営業サイクルが3〜6ヶ月と長期化 |
| **対策1** | 税理士会の支部セミナーや業界誌への寄稿でリード獲得。コールドコールではなく、業界コミュニティ経由の信頼構築型営業 |
| **対策2** | 「1ヶ月無料トライアル + 成果保証」で導入ハードルを下げる。トライアル中に実際の証憑で仕訳精度を体験してもらう |
| **対策3** | 初期の導入事務所にリファラルプログラム（紹介1件あたり1ヶ月無料）を提供。税理士同士のネットワークを活用した口コミ拡散 |

## 4. 請負事業とのシナジー

### 4-1. 技術面のシナジー

```
請負案件（大手向け）        自社サービス（中小向け）
       |                          |
       v                          v
  大規模Webアプリ開発     AI経理パートナー開発
       |                          |
       +--- 共通技術基盤 ----------+
       |   (Next.js, Supabase,    |
       |    API設計, インフラ)      |
       |                          |
       v                          v
  請負で得た技術力 ───→ 自社サービスの品質向上
  自社サービスの実績 ──→ 請負案件の提案力向上
```

- **技術スタックの共通化**: 請負でもNext.js + Supabaseの案件を積極受注し、チームの習熟度を高める
- **AIノウハウの蓄積**: 自社サービスで得たLLM活用のノウハウを、請負案件の「AI機能追加」提案に転用
- **コードの再利用**: 認証、ファイルアップロード、チャット機能などの共通モジュールを請負・自社で共有

### 4-2. 営業面のシナジー

| 方向 | シナジー内容 |
|------|-------------|
| 請負 → 自社 | 大手クライアントの経理部門にAI経理パートナーを紹介。顧問税理士経由での導入を提案 |
| 自社 → 請負 | AI経理パートナーの導入事務所から「顧問先のWebサイト制作」「業務システム開発」の受注 |
| ブランド強化 | 「AIに強いWeb開発会社」というポジションで、請負の単価向上（AI案件はプレミアム） |

### 4-3. リソース面のシナジー

- **開発リソースの柔軟配分**: 請負の繁閑に合わせてエンジニアを自社サービスにアサイン。閑散期を有効活用
- **外注ネットワークの活用**: 請負で構築した外注エンジニアのネットワークを、自社サービスの機能開発にも活用
- **収益の安定化**: 請負（フロー収益）+ 自社サービス（ストック収益）で収益構造を安定化

### 4-4. 具体的なアクションプラン

| 時期 | アクション |
|------|-----------|
| 即時 | 請負案件でNext.js + AI機能の提案を増やし、技術蓄積 |
| MVP開発中 | 請負クライアントの経理担当にヒアリング（市場調査を兼ねる） |
| ローンチ後 | 請負クライアント経由で税理士事務所を紹介してもらう |
| 1年後 | 「AI経理パートナー導入事務所」の顧問先からWeb開発案件を受注 |
| 2年後 | AI案件の請負単価を1.5倍に設定（実績に基づくプレミアム） |
